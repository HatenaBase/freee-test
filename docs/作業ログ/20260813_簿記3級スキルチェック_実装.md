## 実装内容

### boki/index.html

既存 `index.html` からの主な変更点。

1. 出題: `NUM_QUESTIONS = 20`。`CATEGORY_QUOTAS` で単元別の固定枠 3/3/3/3/2/4/2 を定義し、単元ごとに必須問題（`required`）を優先、残りをランダム抽出する。プールが枠に足りない単元がある場合のみ、残りのプールから補充して出題数を維持する（ダミー14問運用のための保険）。
2. 合否表示の廃止: `PASS_RATE`・合格ラインのマーカー・合格/不合格のバッジと文言をすべて削除。代わりに `LEVELS`（80/60を境界とする3段階）でレベル判定し、アイコン・見出し・推奨アクション文を表示する。結果画面には「このスキルチェックに合否判定はありません」の注記も出す。
3. 単元別正答率: 出題された問題を `category` で集計し、表（単元名／正答数・出題数／バー／正答率）で表示する。80%以上は緑、60%未満はアンバーでバーを色分け。「1単元あたり2〜4問のため精度は粗め」の注記つき。振り返りカードにも単元名を表示する。
4. 受験回数制限の無効化: `DEFAULT_MAX_ATTEMPTS` / `isAttemptLimitReached()` / 上限警告ボックスを削除。`attempts` は開始画面の「受験履歴」行と `latest_pct` / `latest_level` の表示にのみ使う（記録は継続）。
5. 問題データ: `fetch('questions.json')` は `boki/` 配下の相対パスのため `boki/questions.json` を読む。
6. localStorage: `boki_SkillCheckResults_` / `boki_SkillCheckProgress_` / `boki_SkillCheckPending_` に変更し、同一オリジンの修了認定テスト（`freeeTest*`）と名前空間を分離。
7. 文言: タイトル・ヘッダーを「簿記3級 スキルチェック」に変更。開始画面に「合否はありません。現在の理解度を確認するテストです。」のリード文と、判定・受験回数（制限なし）の説明を追加。
8. GAS連携: 検証GETに `test_type=skillcheck` を付与。結果POSTに `test_type` / `level` / `levelLabel` / `categories`（単元別集計）を追加。

流用機能（中断復帰24時間・離脱警告・送信再送・未回答ジャンプ・管理者プレビュー・過去結果閲覧）は既存仕様のまま維持。

### boki/questions.json

単元7区分×2問＝14問のダミー。各問に `id`（1始まり）・`category`・`required`（単元ごとに1問true）・`question`・`choices`・`answer`・`explanation` を持つ。JSONはコメントを書けないため、ダミーである旨と本番40問への差し替え前提は README 側に記載した。

注意: ダミーのままでは1単元2問しかないため、実際の出題は20問ではなく14問（各単元2問）になる。本番40問に差し替えると設計どおり20問になる（後述の検証で確認済み）。

### gas/Code.gs

既存関数は1つも書き換えず、`doGet` / `doPost` の分岐と `onOpen` のメニュー追加のみに手を入れた。

- `doGet`: `test_type=skillcheck` のときだけ `validateSkillCheckToken()` へ。パラメータなしは従来どおり `validateToken()`。
- `doPost`: `body.test_type === 'skillcheck'` のときだけ `recordSkillCheckResult()` へ。
- 追加関数: `validateSkillCheckToken` / `recordSkillCheckResult` / `skillCheckCategoryValues` / `skillCheckResultHeaders` / `ensureSkillCheckResultHeaders` / `setupSkillCheckResultSheet` / `updateSkillCheckTokenStats` / `generateSkillCheckTokens` / `generateSkillCheckUrls` / `generateSkillCheckAdminUrls` / `writeSkillCheckUrls`。
- 使用シート: 「スキルチェック_トークン管理」「スキルチェック_結果」。結果行は基本10列（timestamp/token/name/org/score/total/pct/level/level_label/elapsed）＋単元別14列（7単元×正答・出題）の計24列。
- 再送の二重記録防止は既存の `isAlreadyRecorded()` をそのまま共用（A列timestamp・B列tokenで判定）。`formatElapsed()` / `generateToken()` / `getSheet()` も共用。
- シートが存在しない場合は例外を投げず `valid:false / reason:'no_sheet'` またはエラーJSONを返す（シート作成前に受験URLが開かれても500にしない）。

### GAS側の検証（Nodeスタブ）

`gas/Code.gs` を Node の `vm` で読み込み、`SpreadsheetApp` / `ContentService` をスタブして、上記の実POSTペイロードをそのまま流した。15項目すべてPASS。

- スキルチェックGET検証: 有効トークンで `valid:true`、`status=disabled` で `valid:false / disabled`
- 既存GET検証（`test_type` なし）: 従来どおり `maxAttempts` を含む応答（回帰なし）
- 結果記録: 24列の見出しが空シートに自動生成され、行の長さが見出しと一致。決算整理の正答/出題＝2/4、level＝B、level_label＝「理解度: あと一歩」、elapsed＝「0分23秒」
- トークン統計: attempts=1、latest_pct=70%、latest_level、status=受験済
- 再送（同一timestamp）: `{success:true, duplicate:true}` で行が増えない
- 既存の修了テストPOST（`test_type` なし）: 「テスト結果」に従来どおり1行追加され、「スキルチェック_結果」には混入しない。「トークン管理」の attempts/latest_result も従来どおり更新

未検証: 実スプレッドシート・実デプロイでの疎通（依頼範囲外）。`onOpen` のメニュー追加は実UIでは未確認（スタブ上で例外が出ないことのみ確認）。

## 依頼範囲外の気づき（作業はしていない）

- `boki/index.html` は既存 `index.html` と共通ロジックが多い（中断復帰・再送・未回答パネルはほぼ同一）。今後どちらかを直すときは両方に反映が必要になる。共通JSの切り出しは今回スコープ外としたが、3ページ目を作る段階では検討の価値がある。
- `gas/Code.gs` のURL生成系（`generateUrls` / `generateAdminUrls` と `writeSkillCheckUrls`）も同様に重複している。既存関数を触らない方針を優先して重複を許容した。
- 本番40問を投入する際は、`category` の表記が `boki/index.html` の `CATEGORY_QUOTAS` および `gas/Code.gs` の `SKILL_CHECK_CATEGORIES` と1文字も違わないこと、必須問題が各単元の枠数以下であることを確認する必要がある（表記ゆれがあると枠から漏れ、余り枠の補充扱いになる）。
