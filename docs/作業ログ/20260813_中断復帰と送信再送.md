## 機能A: 試験途中の自動保存と再開

### 保存

- キー `freeeTestProgress_<token>`（`PROGRESS_PREFIX`）に単一オブジェクトで保存。構造は `{savedAt(ISO), shuffledQuestions, answers, currentIndex, elapsed(秒)}`。
- `shuffledQuestions` は選択肢シャッフル済み・`answer` が並べ替え後のキーに書き換わった配列をそのまま保存する。これにより復元時に問題文・選択肢の並び・正解マッピングが完全に一致する（`buildQuestionSet()` を再実行しない）。
- `saveProgress()` の呼び出し箇所は `startTest()` / `resumeTest()`（開始直後）・`selectChoice()`（回答選択時）・`nextQuestion()` / `prevQuestion()` / `goToQuestion()`（問題移動時）。`returnToSubmit()` と未回答パネルからのジャンプは `goToQuestion()` 経由なのでカバーされる。
- 保存・読み込み・削除はすべてtry/catch。容量超過・プライベートモードでも `console.warn` に落として受験フローは止めない。
- `isAdmin` または `testInProgress === false` のときは書き込まない。`testInProgress` はテスト画面表示中だけtrueで、`doSubmit()` 冒頭でfalseに戻す。

### 復元

- ページ読込時（`DOMContentLoaded` の末尾）に `renderResumeBox()` を呼ぶ。`isAdmin` は即return。受験回数上限に達している場合は `clearProgress()` してボックスを出さない。
- `loadProgress()` は「JSONとして読める」「`shuffledQuestions` が非空配列」「`savedAt` が24時間以内（`PROGRESS_TTL_MS`）」をすべて満たす場合だけ返す。期限切れならその場で破棄。壊れたJSONはnull扱いで通常フローに戻る。
- 再開ボックスは開始カードの先頭に配置。文言は「受験途中のデータがあります」＋「保存: 2026/08/13 15:57 / 回答済み: 10/50問」。日時は既存の `formatDateJa()`（Asia/Tokyo）を再利用。
- 「続きから再開する」→ `resumeTest()`。保存済みの `shuffledQuestions` / `answers` / `currentIndex` を復元し、`startTime = Date.now() - elapsed*1000` でタイマーを継続してテスト画面へ。`currentIndex` は配列長でクランプする。
- 「最初からやり直す」→ `restartFromScratch()`。進捗を破棄してから `startTest()` を呼ぶ（新しい出題セット・回答リセット・タイマー0から）。

### 破棄のタイミング

`doSubmit()` 冒頭（提出実行時、adminを除く） / `loadProgress()` での24時間超過検知時 / 「最初からやり直す」 / 受験回数上限到達時。

## 機能B: 試験中の離脱警告

- `beforeUnloadHandler` は `e.preventDefault()` + `e.returnValue = ''`（Chromeの現行仕様ではpreventDefaultだけで足りるが、古い実装向けにreturnValueも残す）。
- 有効化は `startTest()` と `resumeTest()`、無効化は `doSubmit()` 冒頭。結果画面・トップ画面では登録されていない。

## 機能C: 結果送信の失敗対策

- 送信を `sendResult(payload)` に切り出し、`AbortController` + 15秒（`SUBMIT_TIMEOUT_MS`）のタイムアウトを付けた。`finally` でタイマーをクリアする。`mode:'no-cors'` は据え置きのため、判定できるのは「fetchがrejectしたか」だけ（HTTPステータスは読めない）。
- reject時はペイロードを `freeeTestPending_<token>`（`PENDING_PREFIX`）に保存。成功時は既存のpendingを削除する。adminは保存しない。
- 警告ボックスは結果画面（`#pending-box-result`）とトップ画面（`#pending-box-start`）の2箇所。文言は「結果の送信に失敗しました」「通信環境をご確認のうえ再送してください」＋「結果を再送する」。表示制御は `renderPendingBoxes()` が両方まとめて行い、`showResult()` とページ読込時・`backToTop()` から呼ぶ。
- 再送 `retryPending(btn)` はボタンを「送信中...」にして無効化し、成功したらpendingを破棄して `showPendingSent()` で緑の「結果を送信しました」に差し替える。失敗したらボタンを元に戻してボックスを維持する。

### GAS側の二重記録防止

- `recordResult` は追記前に `isAlreadyRecorded(sheet, token, timestamp)` を見る。テスト結果シートのA列(timestamp)・B列(token)だけを読み、一致する行があれば `appendRow` も `updateTokenStats` も呼ばずに `{success:true, duplicate:true}` を返す。
- 判定は「文字列そのまま比較」と「`timestampKey()` によるエポックms比較」のOR。前者はISO文字列がテキストのまま保存されているケース、後者はシート側が日付値に変換しているケースに対応する。token・timestampとも `trim()` して比較する。

## 判断根拠・依頼範囲外の細かい判断

1. 再開ボックス表示中は「テストを開始する」ボタンを隠した。「最初からやり直す」と並ぶと同じ操作が2つ見え、誤って進捗を捨てる導線になるため。破棄後は `renderResumeBox()` が開始ボタンを戻す。
2. `doSubmit()` の進捗破棄を `if (!isAdmin)` で囲んだ。管理者プレビューは受験者と同じtokenのURL（`&admin=1`）なのでキーが同一で、同一ブラウザで受験途中の人がプレビューを提出すると進捗を消してしまうため。
3. 結果画面の警告ボックスは「pendingがlocalStorageに存在するか」だけで出し分ける。過去結果を履歴から開いた場合も出るが、実際に未送信の結果が残っている事実は正しいのでそのままにした。
4. `shuffledQuestions` をそのまま保存する方式のため、進捗データは50問分（実測 約60KB）になる。localStorage上限（5MB前後）に対して十分小さい。
