## 機能1: 受験回数の上限

### GAS側（gas/Code.gs）

- リポジトリ内のCode.gsは古かったため、指示にあったデプロイ済み最新版で全面置き換えてから修正した。
- `validateToken` に `max_attempts` 列の探索を追加し、応答JSONに `maxAttempts` を追加。
- 判定は `resolveMaxAttempts()` に切り出し。空欄・列なし・非数値・0以下はすべて既定値の2を返す（`DEFAULT_MAX_ATTEMPTS` 定数）。
- 書き込み系（`updateTokenStats`）は変更していない。max_attempts列は運用側で手動追加する想定（自動追加すると既存の列自動追加ロジックの並び順を崩すため）。

### 画面側（index.html）

- `getMaxAttempts()` / `isAttemptLimitReached()` を追加。`maxAttempts` が来なければ画面側でも2にフォールバックするので、旧GASがデプロイされたままでも既定2回で動く。
- `renderAttemptInfo()` が受験履歴の行と、開始ボタン／警告ボックスの出し分けを担当。上限到達時は `#btn-start` を非表示にし、赤枠の `.limit-box` に指定文言を表示する。受験者名・受験履歴・過去結果一覧は表示したまま。
- `startTest()` の冒頭でも `isAttemptLimitReached()` を見て早期returnするため、コンソールから直接呼んでも開始できない。
- 注意事項の該当行を「受験可能回数は2回までです（延長受講の方のみ3回目受験可）。合否にカウントされるのは2回目の結果までです。」に差し替え。
- GAS到達不可時のフォールバック `{attempts: 0}` は指示どおり据え置き。maxAttemptsは未定義→2扱い、attempts=0なので受験可能。

## 機能2: 過去の受験結果

- キー `freeeTestResults_<token>` に配列で追記保存。1件の構造は `{date(ISO), score, total, pct, passed, elapsed, review[]}`、review要素は `{question, userText, correctText, correct, explanation}`。userTextは「B. 選択肢文」または「未回答」。
- `saveResult()` / `loadStoredResults()` はどちらもtry/catchで、書き込み失敗（容量・プライベートモード）も壊れたJSONの読み込みも握りつぶす。提出フローは止まらない。
- 開始画面に「過去の受験結果」カードを追加。第N回 / 受験日時（`toLocaleString('ja-JP', {timeZone:'Asia/Tokyo'})`）/ 点数% / 合否バッジを一覧表示し、クリックで `showResult(保存データ)` を呼んで結果画面を再表示する。保存データが0件ならカードごと非表示。
- 結果画面にトップに戻るボタンを2箇所（スコアカード内・振り返りの下）追加。既存のCSS変数・カード様式を踏襲した控えめなアウトラインボタン。
- `showResult()` は引数を結果オブジェクト1つに変更し、`shuffledQuestions` / `answers` を直接参照しない形にリファクタリング。提出直後も過去分も同じ経路で描画する。組み立ては `buildResultData()`。表示内容・デザインは従来どおり（受験日時の1行のみ追加）。
- adminモードでは保存も一覧表示も行わない（`doSubmit` は保存前にreturn、`renderHistory` は `isAdmin` で空扱い）。

## 依頼範囲外だが必要だった判断

「トップに戻る」ボタンを付けたことで、リロードせずに同一セッション内で再受験できる経路が新たに生まれた。これを放置すると回数制限が素通りするため、以下2点を入れた。

1. 提出成功後に `tokenData.attempts` をローカルでも+1し、`latestPct` / `latestResult` を更新して `renderAttemptInfo()` を呼ぶ。トップに戻った時点で上限判定とヘッダーの受験履歴が最新になる。
2. `startTest()` で `answers` / `currentIndex` を初期化し、出題セットを組み直す（初期化処理を `buildQuestionSet()` に切り出して再利用）。これがないと2回目の受験に1回目の回答が残る。

## 検証

ローカルにモックGASサーバー（validate応答を返すPython http.server）を立て、Playwrightで実ブラウザ検証した。検証用ファイルはscratchpad内のみでリポジトリには入れていない。

| ケース | 結果 |
|---|---|
| attempts=2 / max_attempts空欄 | 開始ボタン非表示・指定文言表示。`startTest()` 直接呼び出しでも開始画面のまま |
| attempts=2 / max_attempts=3 | 開始可能（maxAttempts=3） |
| attempts=3 / max_attempts=3 | 開始不可 |
| max_attempts が ''/null/undefined/'abc'/0 | すべて2にフォールバック |
| 受験→提出→リロード | 過去結果一覧に第1回が出る。クリックで50問の振り返りまで再表示（正誤・正解・解説とも一致） |
| 未回答のまま提出 | 保存データのuserTextが「未回答」で1件記録される |
| 同一セッションで2回目受験→トップに戻る | 第1回・第2回が並び、attempts=2で上限に到達し開始ボタンが消える |
| admin=1 | 上限判定なし（attempts=3でも開始可）・localStorage保存なし・過去結果一覧非表示 |
| localStorage.setItem が例外を投げる | 例外は外に漏れず、結果画面は正常表示 |
| 375px幅 | 横スクロールなし |

index.html内のJSとCode.gsはいずれも `node --check` 構文チェック済み。

## 補足（改善案・作業はしていない）

localStorageは端末・ブラウザ単位なので、受験者が別端末で開くと過去結果は見えない。正はスプレッドシートの「テスト結果」シートである旨をREADMEに明記した。端末をまたいで見返させる必要が出た場合は、GASにtoken別の結果取得アクションを足す形が素直。
